# Basic KAWK PWA contract

UI author: Claude Code Fable 5.1, required by the user. Implement static assets only in `agent/web/`; do not edit backend modules. Simple responsive testing interface, installable. Product name KAWK. No framework required. Do not copy PSI.

Bun serves `/` and assets; service worker, manifest and icons are public. API requests are same-origin. Provider secrets never enter the browser.

- Session: the local page automatically calls same-origin `POST /v1/client/session`, body `{}`, with no Authorization header. A matching localhost/127.0.0.1 Origin sets an HttpOnly cookie. No token entry or login screen. Re-establish the session after a 401/runtime restart; retry unavailable connections at a bounded interval. Bearer token authentication remains available for scripts. `DELETE /v1/client/session` invalidates a session.
- Runtime: `GET /v1/status`, `/v1/tasks`, `/v1/reminders`, `/v1/notifications`, `/v1/capture/status`. Render errors honestly.
- Notifications: EventSource `/v1/notifications/stream`, event `notification` JSON `{id,text,refs,createdAt,expiresAt}`. Render via textContent. Ack button posts `/v1/notifications/{encodeURIComponent(id)}/ack` (never auto-ack).
- Push: `GET /v1/push/key` returns `{publicKey}`. Explicit button requests permission, registers `/sw.js`, subscribes pushManager (URL-safe base64 decoded key), POST `/v1/push/subscriptions` subscription.toJSON(). DELETE same path `{endpoint}`. SW receives `{id,title,body,url}`, showNotification tag=id; click focuses/opens `/`. Never cache `/v1/*` or authentication. Offline shell only, no fake offline upload success.
- Manual test utterance: POST `/v1/events` body `{events:[{id:crypto.randomUUID(),deviceId:'pwa',streamId:'manual',revision:0,kind:'transcript',final:true,sourceStart:epochMs,sourceEnd:epochMs,text,confidence:1,speakerId:null,personIds:[],provenance:'pwa-manual',timing:{method:'capture',clockSessionId:'manual',uncertaintyMs:50}}]}`.
- Clock: GET `/v1/time` -> `{receivedAt,sentAt,timeZone}`. Three samples; offset=((receivedAt-clientSent)+(sentAt-clientReceived))/2, uncertainty=(roundTrip-(sentAt-receivedAt))/2. Choose minimum uncertainty. Resync every30s. Correct capture epochs using offset; do not upload unsynchronized captures as exact.
- Camera: explicit Start getUserMedia; JPEG canvas long side<=640 quality .75, about2fps, one upload in flight. POST `/v1/capture/frame` JSON `{id:uuid,deviceId:'pwa',streamId:cameraSessionUUID,capturedAt:correctedEpochMs,uncertaintyMs:clockErrorPlus50,imageBase64:base64WithoutPrefix}`. Returns202 `{accepted:true,id}`. Local preview; stop releases tracks/timers. No camera access on load.
- Microphone: same-origin WebSocket `/v1/capture/audio` uses session cookie. First send `{type:'start',deviceId:'pwa',streamId:uuid,capturedAt:correctedEpochMs,uncertaintyMs:clockErrorPlus50}`; await `{type:'ready'}`, then send `{type:'audio-start',capturedAt:correctedEpochMs,uncertaintyMs:clockErrorPlus50}` immediately before the FIRST captured PCM sample. Discard audio before cloud readiness. Then binary mono PCM16 LE at16000Hz. Use AudioWorklet and bounded resampling. First sample should correspond to reported capturedAt (send start only once microphone ready; backend reports cloud-ready delay). No stale queued audio; fresh stream UUID on reconnect. Server sends `{type:'transcript',event}` and `{type:'error',message}`. Stop closes WS, audio context and tracks. Reuse our own prototype audio/resampler patterns if useful.
- GET `/v1/people` -> `{people:[{id,name,imageUrl}]}` optional gallery.

UI: connection/session status, start/stop camera+mic, preview and live transcripts, notifications and ack, pending reminders, tasks, test utterance input. Camera/background push on a phone requires HTTPS; localhost works on desktop. Do not put internal provider details into ordinary flows.
